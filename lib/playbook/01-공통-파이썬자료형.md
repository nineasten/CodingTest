# 공통: 파이썬 자료형 선택

## 1. 언제 이 기술인가 — 문제 속 신호
모든 문제의 시작점. "존재하는지 빠르게 확인", "중복 제거", "순서를 유지해야", "앞/뒤에서
넣고 빼야" 같은 문구가 자료형 선택을 결정한다. 자료형을 잘못 고르면 로직은 맞아도
시간초과가 난다.

## 2. 상황별 한국어 설명 + 예시 코드

### 상황 A: "포함되어 있는지"를 반복해서 확인해야 할 때 → set
`x in list`는 O(N), `x in set`은 평균 O(1). N이 크면 이 차이가 시간초과를 가른다.
```python
seen = set(arr)
if target in seen: ...
```

### 상황 B: 값과 값을 짝지어 빠르게 찾아야 할 때 → dict
"이름으로 나이를 찾는다", "누적 개수를 센다" 류. `collections.Counter`는 개수 세기 전용
dict의 상위호환이다.
```python
from collections import Counter
cnt = Counter(arr)          # {값: 개수}
cnt.most_common(3)          # 가장 흔한 3개
```

### 상황 C: 앞/뒤 양쪽에서 넣고 빼야 할 때 → deque
`list.pop(0)`은 O(N)이라 큐로 쓰면 안 된다. 큐/덱은 무조건 `collections.deque`.
```python
from collections import deque
q = deque(arr)
q.popleft()   # O(1), list.pop(0)은 O(N)이라 절대 쓰지 말 것
q.appendleft(x)
```

### 상황 D: 순서 없이 중복만 없애면 될 때 → set, 순서를 지켜야 할 때 → dict.fromkeys
```python
unique_no_order = set(arr)
unique_keep_order = list(dict.fromkeys(arr))   # 파이썬 3.7+에서 dict는 삽입 순서 보존
```

### 상황 E: 짝을 지어 정렬·비교해야 할 때 → tuple
튜플은 리스트와 달리 해시 가능해서 set/dict의 키로 쓸 수 있다. 좌표 `(r, c)`를
방문 체크할 때 유용.
```python
visited = set()
visited.add((r, c))
```

## 3. 자주 하는 실수
- 큰 리스트에서 `x in list`를 반복 — O(N²)이 되어 시간초과. set/dict로 바꿀 것
- 큐를 `list`로 만들고 `pop(0)` — deque로 바꿀 것
- 딕셔너리 순회 중 딕셔너리를 수정 — `RuntimeError`. `list(d.items())`로 복사 후 순회

## 4. Python 잡기술
- `dict.get(key, default)` — 키가 없을 때 기본값. `if key in d` 검사를 줄여줌
- `collections.defaultdict(int)` — 없는 키 접근 시 자동으로 0 생성, 누적합에 유용
- 리스트 컴프리헨션이 for문보다 대체로 빠르다: `[x*2 for x in arr if x > 0]`
