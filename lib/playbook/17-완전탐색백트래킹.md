# 완전탐색 · 백트래킹

## 1. 언제 이 기술인가 — 문제 속 신호
"가능한 모든 경우를 확인", "N이 작다(≤11이면 순열, ≤20이면 부분집합)", "조건을 만족하는
배치를 찾아라"(N-Queen류). 03번(복잡도감각) 표로 N을 보고 "이거 완전탐색으로 되겠다"를
먼저 판단하는 게 시작점.

## 2. 상황별 한국어 설명 + 예시 코드

### 상황 A: 모든 순열을 시도 (순서가 의미 있을 때)
"모의고사" 문제처럼 3명의 수포자가 각자 정해진 패턴으로 답을 찍고, "가장 많이 맞힌
사람"을 구하는 데엔 순열이 필요 없지만, 만약 "3자리 숫자 카드로 만들 수 있는 모든
번호"처럼 **순서가 다르면 다른 결과**로 쳐야 하는 문제라면 순열을 쓴다. `[1,2,3]`으로
만들 수 있는 3자리 수는 `123, 132, 213, ...` 여섯 가지다.
```python
from itertools import permutations
for perm in permutations([1, 2, 3]):   # (1,2,3), (1,3,2), (2,1,3), ... 총 6가지
    number = int(''.join(map(str, perm)))
```

### 상황 B: 모든 조합을 시도 (순서 무관, 몇 개를 고를지 정해짐)
소수 찾기처럼 숫자 카드 `["1","7"]`에서 카드를 1장 또는 2장 뽑아 만들 수 있는 모든
수를 확인해야 한다면("소수 찾기"류), `"17"`과 `"71"`은 다른 수지만 "카드 2장을 뽑는
방법 자체"는 `{1,7}` 하나뿐이다 — 뽑은 **뒤에** 순서를 permutations로 다시 고려한다.
```python
from itertools import combinations
for r in range(1, len(cards)+1):
    for combo in combinations(cards, r):   # r장을 고르는 모든 "묶음" (순서 없음)
        ...
```

### 상황 C: 모든 부분집합을 시도 (2^N)
전구 3개(`n=3`)를 켜고 끄는 모든 조합을 확인해야 한다면, 각 전구가 "켜짐/꺼짐" 두
상태를 가지므로 총 2³=8가지 조합이 있다. `mask`를 이진수로 보고 k번째 비트가
1이면 "k번 전구가 켜짐"으로 해석하면, 반복문 없이도 모든 조합을 숫자 하나로 표현할
수 있다.
```python
n = 3
for mask in range(1 << n):           # 0 ~ 7 (2^3 - 1)
    subset = [i for i in range(n) if mask & (1 << i)]
    # mask=5(=0b101)이면 subset=[0, 2] → 0번, 2번 전구만 켜진 상태
```

### 상황 D: 조건에 안 맞으면 즉시 포기 (가지치기 = 백트래킹)
4-Queen 문제(4×4 체스판에 퀸 4개를 서로 안 겹치게 놓는 방법의 수)에서, 퀸을 4개 다
놓은 뒤에 "겹치는 게 있는지" 검사하면 4⁴=256가지를 전부 만들어야 해서 느리다. 대신
**한 줄에 퀸을 놓을 때마다** 그 즉시 "이미 놓은 퀸과 같은 열/대각선인지"를 확인해서,
안 되면 그 갈래는 아예 더 진행하지 않는다(가지치기). 시도했다가 실패하면 반드시
방금 놓은 표시를 지우고(되돌리기) 다음 갈래로 넘어간다.
```python
n = 4
count = 0
def backtrack(row, cols, diag1, diag2):
    global count
    if row == n:
        count += 1
        return
    for col in range(n):
        if col in cols or (row-col) in diag1 or (row+col) in diag2:
            continue                          # 가지치기: 이 col은 시도할 필요도 없음
        cols.add(col); diag1.add(row-col); diag2.add(row+col)
        backtrack(row+1, cols, diag1, diag2)
        cols.remove(col); diag1.remove(row-col); diag2.remove(row+col)  # 되돌리기 필수
backtrack(0, set(), set(), set())   # count == 2 (4-Queen의 해는 2가지)
```

### 상황 E: 격자/도형을 겹쳐보며 맞는 배치를 찾기 (카펫류)
얼룩(노란색) 칸이 10개, 갈색 칸이 8개인 격자무늬 카펫에서 "가로 몇 칸 × 세로 몇 칸"
크기였는지 역산해야 한다고 하자("카펫"류). 전체 칸 수(노랑+갈색=18)의 약수 쌍을
가로·세로 후보로 놓고, 각 후보에서 "테두리(갈색) 칸 수가 실제로 8인가"만 확인하면
된다. 넓이로 후보를 먼저 좁혔기 때문에 완전탐색이라도 몇 번 안 돈다.

## 3. 자주 하는 실수
- 백트래킹에서 **되돌리기(상태 원복)를 빼먹음** — 다음 갈래를 탐색할 때 이전 선택이
  남아있어 오답
- `permutations`/`combinations`를 리스트로 바로 변환해 메모리를 낭비 — 필요할 때만 순회
- N이 20을 넘는데 완전탐색을 시도 — 03번 표를 다시 확인하고 접근을 바꿀 것

## 4. Python 잡기술
- `itertools.product(*iterables)` — 여러 리스트에서 하나씩 골라 만드는 모든 조합 (중복 허용)
- `itertools.combinations_with_replacement` — 같은 원소를 여러 번 골라도 되는 조합
