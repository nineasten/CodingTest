# 공통: 복잡도 감각

## 1. 언제 이 기술인가 — 문제 속 신호
모든 문제에서 코딩을 시작하기 전에. 제약(N의 범위)을 보는 즉시 "이 접근이 시간 안에
도는가"를 판단해야 한다. `/next`가 문제를 낼 때 이미 계산해서 알려주지만, **막혔을 때
스스로 판단할 수 있어야** 힌트 1단계를 바로 통과한다.

## 2. 상황별 한국어 설명

### 상황 A: 1초의 연산 횟수 감 잡기
Python은 대략 **1초에 2000만~1억 연산** (언어 자체가 느려서 C++보다 5~10배 느리다고
가정하는 게 안전). 프로그래머스는 보통 넉넉하게(수 초) 잡아주지만 기준은 비슷하게 잡는다.

### 상황 B: N 범위 → 허용 복잡도 표
| N의 크기 | 허용되는 복잡도 | 전형적 접근 |
|---|---|---|
| N ≤ 11 | O(N!) | 순열, 완전탐색 |
| N ≤ 20 | O(2^N) | 부분집합 완전탐색, 비트마스크 |
| N ≤ 500 | O(N³) | 3중 for문, 플로이드류 |
| N ≤ 5,000 | O(N²) | 2중 for문 |
| N ≤ 1,000,000 | O(N log N) | 정렬, 힙, 이분탐색 |
| N ≤ 10,000,000+ | O(N) 또는 O(log N) | 투 포인터, 해시, 그리디 |

### 상황 C: 이중 반복이 숨어있는 경우 주의
`for x in arr: if x in other_list` 는 겉으론 한 줄이지만 `in`이 O(N)이면 전체가 O(N²)다.
자료형 선택(01번 노트)이 복잡도에 그대로 반영된다는 걸 항상 의식할 것.

### 상황 D: 문제 풀다 막혔을 때 스스로 점검하는 순서
1. 지금 짠 코드(또는 계획)가 최악의 경우 몇 번 도는가?
2. N 범위에 위 표를 대입하면 허용 복잡도는?
3. 둘이 안 맞으면 → 자료구조를 바꿀 수 있는가(01번), 불필요한 재계산을 캐싱할 수 있는가(DP),
   정렬로 탐색을 줄일 수 있는가(이분탐색)를 순서대로 의심한다.

## 3. 자주 하는 실수
- "제약이 작으니까 대충 짜도 되겠지"라고 판단은 맞는데 실제로는 숨은 반복이 있어 틀림
- 재귀 함수의 복잡도를 안 따지고 그냥 씀 — 재귀는 각 호출 내부 반복까지 곱해서 계산

## 4. Python 잡기술
- `timeit`이나 직접 `time.time()`으로 로컬에서 실측 가능하지만, 이 워크스페이스는 로컬
  채점을 안 하므로 **제출 전에 논리로 계산하는 습관**이 더 중요하다
- 재귀 깊이 제한(`sys.setrecursionlimit`) — DFS를 재귀로 짤 때 N이 크면 필요할 수 있음
