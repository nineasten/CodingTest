# 이분탐색

## 1. 언제 이 기술인가 — 문제 속 신호
"정렬된 배열에서 값을 빠르게 찾아라" 뿐 아니라, **"답이 될 수 있는 값의 범위에서 특정
조건을 만족하는 최소/최대 값을 찾아라"**(파라메트릭 서치)도 이분탐색이다. 후자가 시험
빈도가 더 높다 — "입국심사"류.

## 2. 상황별 한국어 설명 + 예시 코드

### 상황 A: 정렬된 배열에서 값 찾기 (표준 이분탐색)
정렬된 예산 목록 `[1,3,2,5,4]`(→정렬하면 `[1,2,3,4,5]`)에서 특정 값이 있는지, 있다면
어디에 넣어야 정렬이 유지되는지 알아야 할 때 직접 `lo`/`hi`로 반복문을 짜지 않고
`bisect` 모듈을 쓰면 한 줄로 끝난다.
```python
import bisect
sorted_arr = [1, 2, 3, 4, 5]
idx = bisect.bisect_left(sorted_arr, 3)         # 2 — "3"이 들어갈 가장 왼쪽 위치
exists = idx < len(sorted_arr) and sorted_arr[idx] == 3   # True
```

### 상황 B: 파라메트릭 서치 — "답 자체"를 이분탐색으로 찾기
심사관 여러 명이 각자 `times = [7, 10]`분씩 걸려 1명을 심사하고, `n=6`명을 모두
심사하는 데 필요한 **최소 시간**을 구한다고 하자("입국심사"류). 여기선 정렬된 배열이
아니라 "1분부터 (가장 느린 심사관 시간 × n)분까지" 같은 **답 후보 범위** 자체를
이분탐색한다. "심사 시간이 `mid`분 주어지면 n명을 다 처리할 수 있는가?"를 판정하는
함수를 만들고, "가능/불가능"이 뒤집히는 경계값을 찾는다.
```python
def is_possible(mid, times, n):
    total = sum(mid // t for t in times)   # mid분 동안 각 심사관이 처리 가능한 인원 합
    return total >= n

times = [7, 10]
n = 6
lo, hi = 1, max(times) * n
while lo < hi:
    mid = (lo + hi) // 2
    if is_possible(mid, times, n):
        hi = mid       # mid분이면 가능하니, 더 짧은 시간도 가능한지 좁혀봄
    else:
        lo = mid + 1    # mid분으론 부족하니 더 늘려봄
answer = lo   # 28 — 6명을 모두 처리하는 데 필요한 최소 시간
```

### 상황 C: 개수/삽입 위치를 한 번에 구하기
정렬된 배열 `[1, 2, 2, 2, 3]`에서 "값 2가 몇 개 있는가"를 세고 싶다면, `2`가 들어갈
가장 왼쪽 위치와 가장 오른쪽 위치의 차이가 곧 개수다.
```python
arr = [1, 2, 2, 2, 3]
left = bisect.bisect_left(arr, 2)     # 1
right = bisect.bisect_right(arr, 2)   # 4
count_of_2 = right - left              # 3
```

## 3. 자주 하는 실수
- `lo`, `hi` 갱신 규칙에서 등호를 잘못 넣어 **무한루프**에 빠짐 — `while lo < hi`와
  `while lo <= hi`, `mid`/`mid+1`/`mid-1` 조합을 문제 성격에 맞게 정확히 골라야 함
- 이분탐색은 배열에만 쓴다고 착각 — 상황 B처럼 "탐색 대상이 정렬 가능한 값의 범위"면
  배열이 없어도 쓸 수 있다는 걸 놓침
- `is_possible` 함수의 부등호 방향(`>=` vs `>`)이 문제 조건과 안 맞음

## 4. Python 잡기술
- `bisect` 모듈을 쓰면 직접 이분탐색 루프를 짤 필요가 없는 경우가 많다 (상황 A, C)
- 파라메트릭 서치(상황 B)는 직접 짜야 하므로, **루프 불변식**(lo는 항상 불가능 또는
  경계, hi는 항상 가능 — 방향을 정해두고 시작)을 미리 정하고 코딩하면 실수가 준다
