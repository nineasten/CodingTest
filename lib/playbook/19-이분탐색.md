# 이분탐색

## 1. 언제 이 기술인가 — 문제 속 신호
"정렬된 배열에서 값을 빠르게 찾아라" 뿐 아니라, **"답이 될 수 있는 값의 범위에서 특정
조건을 만족하는 최소/최대 값을 찾아라"**(파라메트릭 서치)도 이분탐색이다. 후자가 시험
빈도가 더 높다 — "입국심사"류.

## 2. 상황별 한국어 설명 + 예시 코드

### 상황 A: 정렬된 배열에서 값 찾기 (표준 이분탐색)
```python
import bisect
idx = bisect.bisect_left(sorted_arr, target)   # target이 들어갈 가장 왼쪽 위치
exists = idx < len(sorted_arr) and sorted_arr[idx] == target
```

### 상황 B: 파라메트릭 서치 — "답 자체"를 이분탐색으로 찾기
배열이 아니라 **"답이 될 수 있는 값의 범위"**를 반으로 쪼갠다. "이 값이면 조건을
만족하는가?"를 판정하는 함수를 먼저 만들고, 그 함수의 결과가 뒤집히는 경계를 찾는다.
```python
def is_possible(mid, *args):
    # "심사 시간이 mid일 때 n명을 다 처리할 수 있는가" 같은 판정 함수
    total = sum(mid // time for time in times)
    return total >= n

lo, hi = 1, max(times) * n
while lo < hi:
    mid = (lo + hi) // 2
    if is_possible(mid):
        hi = mid       # 가능하면 더 작은 값도 가능한지 좁혀본다 (최솟값 찾기 예시)
    else:
        lo = mid + 1
answer = lo
```

### 상황 C: 개수/삽입 위치를 한 번에 구하기
```python
bisect.bisect_left(arr, x)    # x가 들어갈 왼쪽 위치 (중복이면 그 중 가장 왼쪽)
bisect.bisect_right(arr, x)   # x가 들어갈 오른쪽 위치
count_of_x = bisect.bisect_right(arr, x) - bisect.bisect_left(arr, x)
```

## 3. 자주 하는 실수
- `lo`, `hi` 갱신 규칙에서 등호를 잘못 넣어 **무한루프**에 빠짐 — `while lo < hi`와
  `while lo <= hi`, `mid`/`mid+1`/`mid-1` 조합을 문제 성격에 맞게 정확히 골라야 함
- 이분탐색은 배열에만 쓴다고 착각 — 상황 B처럼 "탐색 대상이 정렬 가능한 값의 범위"면
  배열이 없어도 쓸 수 있다는 걸 놓침
- `is_possible` 함수의 부등호 방향(`>=` vs `>`)이 문제 조건과 안 맞음

## 4. Python 잡기술
- `bisect` 모듈을 쓰면 직접 이분탐색 루프를 짤 필요가 없는 경우가 많다 (상황 A, C)
- 파라메트릭 서치(상황 B)는 직접 짜야 하므로, **루프 불변식**(lo는 항상 불가능 또는
  경계, hi는 항상 가능 — 방향을 정해두고 시작)을 미리 정하고 코딩하면 실수가 준다
