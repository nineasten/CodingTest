## 2. 상황별 한국어 설명 + 예시 코드

### 상황 A: 조건이 여러 개 순서대로 적용되는 문제 (연쇄 규칙)
"신규 아이디 추천"류 문제를 생각해보자. 입력 아이디 `"...!@BaT#*..y.abcdefghijklm"`를
① 소문자로 바꾸고 → ② 허용 안 되는 문자 제거 → ③ 마침표 연속을 하나로 → ④ 앞뒤
마침표 제거 → ⑤ 빈 문자열이면 "a"로 → ⑥ 길이 16자 넘으면 자르고 끝 마침표 제거 →
⑦ 3자 미만이면 마지막 글자를 채워서 3자로, 이렇게 **7단계 규칙을 순서대로** 적용해야
`"bat.y.abcdefghi"`가 나온다. 이걸 한 함수에 다 몰아넣으면 중간에 조건 하나를 빠뜨려도
알아채기 어렵다. **규칙 하나당 함수 하나씩** 쪼개서, 순서대로 적용하면 어느 단계에서
틀렸는지 바로 짚어낼 수 있다.
```python
def step1_lower(s): return s.lower()
def step2_filter(s): return ''.join(c for c in s if c.isalnum() or c in '-_.')
def step3_dots(s): ...
def solution(new_id):
    s = new_id
    for step in (step1_lower, step2_filter, step3_dots, step4, step5, step6, step7):
        s = step(s)   # 이전 단계 결과를 다음 단계 입력으로
    return s
```

### 상황 B: 상태를 유지하며 이벤트를 순서대로 처리
"의상 대여점에 사람이 들어오고 나간다"류를 생각해보자. 이벤트가
`["A enter", "A leave", "B enter"]`처럼 시간 순서대로 주어지고, "특정 시점에 매장
안에 몇 명이 있었는가"를 물어본다면, "지금 매장 안에 누가 있는지"라는 **상태**를
변수(여기선 set)로 명확히 유지하면서 이벤트를 하나씩 순서대로 적용해야 한다.
```python
inside = set()
for event in ["A enter", "A leave", "B enter"]:
    name, action = event.split()
    if action == "enter":
        inside.add(name)
    else:
        inside.discard(name)
    # 이 시점의 inside가 "지금 매장 안에 있는 사람들"
```
매 이벤트마다 `inside`(상태)만 갱신하고, 그 시점의 답이 필요하면 그때그때 `inside`를
읽으면 된다 — 전체 이벤트를 다시 훑을 필요가 없다.

### 상황 C: 문자열을 규칙에 따라 변환/파싱
"튜플" 문제처럼 `"{{2},{2,1},{2,1,3},{2,1,3,4}}"`같이 중괄호로 중첩된 문자열이
주어지고, 이걸 실제 파이썬 튜플 `(2, 1, 3, 4)`로 복원해야 한다고 하자. 문자열을 앞에서
부터 한 글자씩 손으로 파싱하면 괄호 짝을 세는 로직에서 실수하기 쉽다. 대신 정규식으로
"중괄호로 둘러싸인 숫자·쉼표 덩어리"를 통째로 뽑아내면 각 원소가 바로 손에 들어온다.
```python
import re
s = "{{2},{2,1},{2,1,3},{2,1,3,4}}"
tokens = re.findall(r'\{[\d,]*\}', s)
# ['{2}', '{2,1}', '{2,1,3}', '{2,1,3,4}'] — 중첩되지 않은 조각들이 순서대로 나옴
```
뽑아낸 토큰들을 길이순으로 정렬하면 등장 순서(=원래 튜플의 순서)가 자연히 복원된다.

### 상황 D: 시뮬레이션 도중 "종료 조건"을 놓치기 쉬운 문제
"모든 사람이 카드를 다 낼 때까지 반복" 같은 문제에서, "언제 멈추는가"를 코드를 짜면서
즉흥적으로 정하면 딱 한 케이스(예: 큐가 빈 채로 한 번 더 도는 경우)가 빠지기 쉽다.
루프를 짜기 **전에** 종료 조건을 말로 먼저 적어본다: "대기열이 비면 끝난다."

```python
from collections import deque
queue = deque([1, 2, 3])
while queue:                 # "큐가 빌 때까지" — 이 한 줄이 곧 종료 조건의 코드화
    cur = queue.popleft()
    ...
```

### 상황 E: 여러 그룹/카테고리별로 집계해야 하는 문제
"성격 유형 검사하기"처럼 응답이 `["ND","OT","ND",...]`처럼 여러 카테고리(성격 지표)에
걸쳐 점수를 쌓고, 마지막에 카테고리별로 어느 쪽 점수가 더 높은지 비교해야 한다고 하자.
각 응답이 어느 카테고리에 몇 점을 더하는지만 정해지면, 나머지는 `defaultdict`로
누적하고 끝에 비교하면 된다. 이때 **동점 처리 규칙**(예: "동점이면 사전순으로 앞선
성향")을 문제 뒷부분에서 반드시 다시 확인한다 — 누락되면 특정 케이스에서만 틀린다.
```python
from collections import defaultdict
score = defaultdict(int)
for answer in answers:
    category, point = interpret(answer)   # 예: ("N", 3)
    score[category] += point
# score = {"N": 12, "D": 8, ...} → 그룹별로 큰 쪽을 골라 최종 유형 결정
```

## 3. 자주 하는 실수
- **문제를 처음 읽을 때 조건 하나를 놓침** — 조건이 5개 이상이면 각 조건을 번호 매겨
  체크리스트로 옮겨 적고, 코드에서 그 번호를 주석으로 남긴다
- 0-index / 1-index 혼동 — 문제가 "1번째"라고 하면 배열 인덱스와 하나씩 어긋남
- 동점·경계값 처리 규칙을 문제 뒷부분(제약조건, 예시 설명)에서 놓침 — 예시를 반드시
  손으로 한 번 따라가 볼 것
- 원본 리스트를 순회하면서 그 리스트를 직접 수정 — 복사본을 만들거나 인덱스를 거꾸로 순회

## 4. Python 잡기술
- `enumerate(arr, start=1)` — 1-index로 세고 싶을 때 바로 사용
- `str.translate`, `re.sub` — 문자 단위 변환을 반복문 없이 한 번에
- `all(...)`, `any(...)` — 여러 조건을 동시에 확인할 때 for문보다 짧고 명확
- `itertools.groupby` — 연속된 같은 값을 그룹으로 묶을 때 (정렬 후에만 의미 있음)
