# 힙

## 1. 언제 이 기술인가 — 문제 속 신호
"가장 작은/큰 값을 반복해서 꺼내야 한다", "매번 최솟값과 최댓값을 다뤄야 한다",
"우선순위대로 처리" — **정렬은 한 번만 할 수 있지만, 힙은 원소가 계속 추가/삭제되는
상황에서 매번 최소/최대를 O(log N)에 유지**해준다는 게 핵심 차이.

## 2. 상황별 한국어 설명 + 예시 코드

### 상황 A: 최솟값을 반복해서 꺼내며 합치는 문제 ("더 맵게"류)
스코빌 지수 `[1, 2, 3, 9, 10, 12]`인 음식들을 "가장 안 매운 두 개를 골라
`더 안매운것 + 덜매운것*2` 공식으로 새 음식을 만들고, 다시 목록에 넣는" 걸 모든
음식이 target(예: 7) 이상이 될 때까지 반복해야 한다. "가장 작은 것 두 개"를 매번
정렬로 찾으면 O(N log N)이 반복마다 드는데, 힙은 "최솟값을 O(log N)에 꺼내고 다시
O(log N)에 넣는" 걸 계속 유지해준다.
```python
import heapq
arr = [1, 2, 3, 9, 10, 12]
heapq.heapify(arr)                    # O(N), 리스트를 힙 순서로 제자리 변환
target = 7
tries = 0
while arr[0] < target and len(arr) > 1:
    a = heapq.heappop(arr)   # 가장 안 매운 것
    b = heapq.heappop(arr)   # 두 번째로 안 매운 것
    heapq.heappush(arr, a + 2*b)
    tries += 1
```

### 상황 B: 최댓값 힙이 필요할 때 (Python heapq는 최소힙만 지원)
"가장 비싼 물건 3개를 순서대로 꺼내고 싶다"처럼 최댓값을 반복해서 꺼내야 하는데,
파이썬 `heapq`는 최소힙만 지원한다. 값을 넣을 때 부호를 반대로 뒤집어 넣으면
"가장 작은 음수 = 원래 가장 큰 값"이 되어 최소힙으로 최댓값 힙을 흉내낼 수 있다.
```python
import heapq
max_heap = []
for price in [3000, 15000, 7000]:
    heapq.heappush(max_heap, -price)   # 부호를 뒤집어서 저장
biggest = -heapq.heappop(max_heap)     # 15000 — 다시 부호를 뒤집어 원래 값으로
```

### 상황 C: 최솟값과 최댓값을 동시에 유지해야 할 때 (이중우선순위큐류)
"삽입 연산은 값을 큐에 넣고, 최댓값 삭제(D 1)나 최솟값 삭제(D -1) 연산은 해당 값을
큐에서 지운다"는 명령이 순서대로 들어올 때("이중우선순위큐"류), 최소힙 하나와
최대힙 하나를 같이 운용한다. 문제는 한쪽 힙에서 값을 지워도 **다른 쪽 힙엔 그 값이
그대로 남아있다는 것** — 힙 내부를 뒤져서 지우는 건 비싸므로(O(N)), 대신 "지워진 값
목록"만 따로 기록해두고, 힙에서 꺼낼 때 그 목록에 있으면 버리고 다음 걸 본다
(지연 삭제).
```python
removed = set()
while min_heap and min_heap[0] in removed:   # 힙 맨 위가 이미 지워진 값이면
    heapq.heappop(min_heap)                   # 버리고 계속 확인
# 이제 min_heap[0]은 "아직 안 지워진 진짜 최솟값"
```

### 상황 D: (우선순위, 값) 튜플을 힙에 넣을 때
작업을 `(마감시각, 작업이름)`처럼 튜플로 힙에 넣으면 마감이 빠른 순서로 자동 정렬되어
꺼내진다. 그런데 마감시각이 같은 두 작업이 있고 작업이름이 서로 비교 불가능한 타입
(예: dict)이면, 힙이 첫 값(마감시각)이 같아서 두 번째 값을 비교하려다가 에러가 난다.
동점일 때 굳이 비교할 필요 없는 값(예: 삽입 순서, 인덱스)을 중간에 끼워 넣으면 이
비교가 거기서 끝나 에러를 막을 수 있다.
```python
import heapq
heap = []
heapq.heappush(heap, (deadline, idx, task_dict))   # idx가 있어 deadline이 같아도 비교가 안전
```

## 3. 자주 하는 실수
- 매번 `sorted(arr)[0]`으로 최솟값을 구함 — O(N log N)을 반복하는 것이라 시간초과.
  힙이 필요한 신호를 놓친 것
- 최댓값 힙을 만든다면서 부호 반전을 깜빡함
- 이중우선순위큐에서 지연 삭제를 안 해서 이미 지운 값이 다시 튀어나옴

## 4. Python 잡기술
- `heapq.heapify(list)` — 이미 있는 리스트를 O(N)에 힙으로 변환 (하나씩 push하면 O(N log N))
- `heapq.nsmallest(k, arr)`, `heapq.nlargest(k, arr)` — 상위 k개만 필요하면 전체 정렬보다 빠름
