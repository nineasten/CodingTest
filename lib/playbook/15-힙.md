# 힙

## 1. 언제 이 기술인가 — 문제 속 신호
"가장 작은/큰 값을 반복해서 꺼내야 한다", "매번 최솟값과 최댓값을 다뤄야 한다",
"우선순위대로 처리" — **정렬은 한 번만 할 수 있지만, 힙은 원소가 계속 추가/삭제되는
상황에서 매번 최소/최대를 O(log N)에 유지**해준다는 게 핵심 차이.

## 2. 상황별 한국어 설명 + 예시 코드

### 상황 A: 최솟값을 반복해서 꺼내며 합치는 문제 ("더 맵게"류)
```python
import heapq
heapq.heapify(arr)                    # O(N), 리스트를 힙으로 제자리 변환
while arr[0] < target and len(arr) > 1:
    a = heapq.heappop(arr)
    b = heapq.heappop(arr)
    heapq.heappush(arr, a + 2*b)      # 예시 규칙
```

### 상황 B: 최댓값 힙이 필요할 때 (Python heapq는 최소힙만 지원)
값을 넣을 때 부호를 반전시켜 "최댓값=최소힙의 최솟값"으로 바꿔치기한다.
```python
max_heap = []
heapq.heappush(max_heap, -val)
biggest = -heapq.heappop(max_heap)
```

### 상황 C: 최솟값과 최댓값을 동시에 유지해야 할 때 (이중우선순위큐류)
힙을 두 개(최소힙 하나 + 최대힙 하나) 운용하되, 삭제된 값이 반대쪽 힙에 남아있을 수
있으므로 **지연 삭제(lazy deletion)**로 처리한다 — 꺼낼 때 이미 삭제된 값이면 버리고
다음 것을 본다.
```python
removed = set()
while min_heap and min_heap[0] in removed:
    heapq.heappop(min_heap)
```

### 상황 D: (우선순위, 값) 튜플을 힙에 넣을 때
튜플은 첫 원소로 비교하고, 같으면 다음 원소로 비교한다 — 두 번째 원소가 비교 불가능한
객체면 에러가 나므로, 동점 시 비교할 필요 없는 값(인덱스 등)을 두 번째로 넣어둔다.
```python
heapq.heappush(heap, (priority, idx, value))
```

## 3. 자주 하는 실수
- 매번 `sorted(arr)[0]`으로 최솟값을 구함 — O(N log N)을 반복하는 것이라 시간초과.
  힙이 필요한 신호를 놓친 것
- 최댓값 힙을 만든다면서 부호 반전을 깜빡함
- 이중우선순위큐에서 지연 삭제를 안 해서 이미 지운 값이 다시 튀어나옴

## 4. Python 잡기술
- `heapq.heapify(list)` — 이미 있는 리스트를 O(N)에 힙으로 변환 (하나씩 push하면 O(N log N))
- `heapq.nsmallest(k, arr)`, `heapq.nlargest(k, arr)` — 상위 k개만 필요하면 전체 정렬보다 빠름
