# 공통: 정렬과 key

## 1. 언제 이 기술인가 — 문제 속 신호
"순서대로 정렬해", "우선순위가 높은 것부터", "여러 기준으로 비교" 가 나오면 정렬 문제다.
정렬 자체는 쉽지만 **기준(key)을 어떻게 세우느냐**가 시험에서 갈린다.

## 2. 상황별 한국어 설명 + 예시 코드

### 상황 A: 기본 오름차순/내림차순
시험 점수 `[85, 60, 95, 70]`을 그냥 순서대로 줄 세우기만 하면 되는 가장 단순한 경우.
```python
arr = [85, 60, 95, 70]
arr.sort()                 # arr 자체가 [60, 70, 85, 95]로 바뀜 (반환값 None)
new_arr = sorted(arr)      # 원본은 그대로 두고 정렬된 "새 리스트"를 돌려받음
arr.sort(reverse=True)     # [95, 85, 70, 60] — 내림차순
```

### 상황 B: 특정 값 기준으로 정렬 (key)
`("Kim", 25), ("Lee", 30), ("Park", 20)`처럼 (이름, 나이) 쌍의 리스트가 있고, **나이
기준으로만** 줄을 세워야 한다고 하자. 튜플 자체를 그냥 정렬하면 이름 알파벳이 먼저
비교돼서 원하는 결과가 안 나온다. `key`에 "정렬 기준이 될 값을 뽑아내는 함수"를 넘기면
그 값만 보고 비교한다.
```python
people = [("Kim", 25), ("Lee", 30), ("Park", 20)]
people.sort(key=lambda x: x[1])   # x[1] = 나이만 보고 비교
# 결과: [("Park", 20), ("Kim", 25), ("Lee", 30)]
```

### 상황 C: 여러 기준으로 정렬 (1순위 다음 2순위)
이번엔 "나이가 많은 순서로 줄을 세우되, 나이가 같으면 이름 사전순으로"처럼 기준이 두
개다. 튜플은 앞 원소부터 순서대로 비교되는 성질이 있으므로, `key`가 `(1순위, 2순위)`
형태의 튜플을 돌려주면 자동으로 "1순위가 같을 때만 2순위를 본다"가 구현된다.
```python
people = [("Kim", 25), ("Lee", 25), ("Park", 30)]
people.sort(key=lambda x: (-x[1], x[0]))
# -x[1]: 나이 내림차순(음수로 뒤집어서), 나이가 같으면 x[0] 이름 오름차순
# 결과: [("Park", 30), ("Kim", 25), ("Lee", 25)]
```

### 상황 D: 문자열을 "숫자처럼" 비교하고 싶을 때 vs "이어붙인 결과"로 비교할 때
`[3, 30, 34, 5, 9]`를 이어붙여 만들 수 있는 가장 큰 수를 만들어야 한다고 하자. 정답은
`"9534330"`이다. 이걸 문자열로 바꿔 그냥 사전순 정렬(`["3","30","34","5","9"]`)하면
`"3"`이 `"30"`보다 사전순으로 앞이라 순서가 틀어진다("330" < "303"이 되어야 맞는데
사전순은 이걸 구분 못함). 대신 "두 후보 a, b를 이어붙였을 때 `a+b`가 큰지 `b+a`가
큰지"를 직접 비교하는 함수를 만들어 정렬 기준으로 쓴다.
```python
from functools import cmp_to_key
def compare(a, b):
    if a + b > b + a: return -1   # a+b가 더 크면 a가 앞에 와야 함
    elif a + b < b + a: return 1
    return 0
arr_str = list(map(str, [3, 30, 34, 5, 9]))
arr_str.sort(key=cmp_to_key(compare))   # ['9','5','34','3','30']
result = ''.join(arr_str)                # "9534330"
```

### 상황 E: 정렬은 하되 원래 인덱스도 알아야 할 때
점수 `[70, 90, 60]`을 정렬하면서 "원래 몇 번째 학생이었는지"도 같이 알아야 할 때
(예: "1등이 원래 명단에서 몇 번이었나?"). `enumerate`로 (인덱스, 값) 쌍을 만든 뒤
값 기준으로 정렬하면 인덱스 정보가 안 사라진다.
```python
scores = [70, 90, 60]
indexed = sorted(enumerate(scores), key=lambda x: x[1], reverse=True)
# [(1, 90), (0, 70), (2, 60)] — 1번 학생이 1등, 원래 인덱스가 그대로 보존됨
```

## 3. 자주 하는 실수
- 문자열 숫자를 그냥 `sort()` — "10"이 "9"보다 사전순으로 앞에 옴. 숫자 비교가 필요하면
  `int()` 변환하거나 상황 D처럼 비교 함수를 직접 정의
- `key=lambda x: -x`로 내림차순을 흉내내다 음수 처리를 깜빡함 — 그냥 `reverse=True` 사용
- `sort()`의 반환값(`None`)을 변수에 저장하려다 버그 — `sort()`는 제자리 정렬, `sorted()`가 반환

## 4. Python 잡기술
- `sort()`는 안정 정렬(stable) — 같은 키를 가진 원소들의 상대 순서가 유지됨. 다단계 정렬에서
  뒤 기준부터 여러 번 `sort()`를 걸어도 안전한 이유
- `min(arr, key=...)`, `max(arr, key=...)` — 전체를 정렬하지 않고 기준값만 필요할 때 더 빠름
