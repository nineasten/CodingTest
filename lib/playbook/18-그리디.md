# 그리디

## 1. 언제 이 기술인가 — 문제 속 신호
"최소/최대를 구하라"인데 완전탐색은 너무 크고(03번 표 초과), "각 단계에서 가장 좋아
보이는 선택을 하면 전체적으로도 최적이 된다"는 게 증명 가능해 보일 때. **"그럴듯해
보인다"만으로 접근하면 위험** — 반례가 있는지 꼭 의심해야 하는 유형.

## 2. 상황별 한국어 설명 + 예시 코드

### 상황 A: 정렬 후 앞에서부터/뒤에서부터 그리디하게 선택
"구명보트"류 — 가장 무거운 사람과 가장 가벼운 사람을 짝지어 보는 식. 정렬이 그리디의
전제조건인 경우가 많다.
```python
arr.sort()
i, j = 0, len(arr) - 1
count = 0
while i <= j:
    if arr[i] + arr[j] <= limit:
        i += 1
    j -= 1
    count += 1
```

### 상황 B: 자릿수/숫자를 지워서 최대/최소 만들기
"큰 수 만들기"류 — 스택처럼 앞에서부터 훑으며, 지금 볼 숫자가 스택 맨 위보다 크면
(그리고 아직 지울 기회가 남았으면) 맨 위를 지운다. 14번 노트의 모노토닉 스택과 사실상
같은 패턴.
```python
stack = []
to_remove = k
for digit in number:
    while stack and to_remove > 0 and stack[-1] < digit:
        stack.pop()
        to_remove -= 1
    stack.append(digit)
result = ''.join(stack[:len(stack)-to_remove])  # 남은 제거 횟수만큼 뒤에서 자름
```

### 상황 C: 구간을 최소 개수로 덮기 (단속카메라류)
구간을 끝나는 지점 기준으로 정렬하고, 이미 커버된 구간이면 넘어가고 아니면 새로 하나
놓는다.
```python
intervals.sort(key=lambda x: x[1])   # 끝나는 지점 기준 정렬
count, last = 0, float('-inf')
for start, end in intervals:
    if start > last:
        count += 1
        last = end
```

## 3. 자주 하는 실수
- **그리디가 항상 최적이라는 증명 없이 "느낌"으로 접근** — 안 되면 DP나 완전탐색으로
  전환할 수 있어야 함 (막혔을 때 유형을 의심하는 것도 힌트 1단계의 역할)
- 정렬 기준을 잘못 잡음 (오름차순/내림차순, 시작점/끝점 기준을 헷갈림)
- 동점 처리 규칙을 안 정함
