# 그리디

## 1. 언제 이 기술인가 — 문제 속 신호
"최소/최대를 구하라"인데 완전탐색은 너무 크고(03번 표 초과), "각 단계에서 가장 좋아
보이는 선택을 하면 전체적으로도 최적이 된다"는 게 증명 가능해 보일 때. **"그럴듯해
보인다"만으로 접근하면 위험** — 반례가 있는지 꼭 의심해야 하는 유형.

## 2. 상황별 한국어 설명 + 예시 코드

### 상황 A: 정렬 후 앞에서부터/뒤에서부터 그리디하게 선택
사람들의 몸무게가 `[70, 50, 80, 50]`이고, 구명보트 하나에 최대 2명, 무게 합 100까지
탈 수 있을 때 필요한 최소 보트 수를 구한다고 하자("구명보트"류). 정렬해서
`[50, 50, 70, 80]`로 만들면, **가장 무거운 사람은 가장 가벼운 사람과 짝지어야
낭비가 없다**는 게 직관적으로 보인다 — 가벼운 사람 두 명을 태우는 것보다 무거운
사람 하나와 가벼운 사람 하나를 태우는 게 자리를 더 효율적으로 쓴다.
```python
arr = sorted([70, 50, 80, 50])   # [50, 50, 70, 80]
i, j = 0, len(arr) - 1           # 가장 가벼운 사람 / 가장 무거운 사람
count = 0
while i <= j:
    if arr[i] + arr[j] <= 100:   # 가장 무거운 사람이 가장 가벼운 사람과 같이 탈 수 있으면
        i += 1                    # 가벼운 사람도 같이 태움
    j -= 1                        # 무거운 사람은 어차피 이번 보트로 보냄
    count += 1
```

### 상황 B: 자릿수/숫자를 지워서 최대/최소 만들기
`"1924"`에서 숫자 2개를 지워 남은 2자리로 가장 큰 수를 만든다고 하자("큰 수 만들기"류,
정답 "94"). 앞에서부터 훑으면서 "지금 보는 숫자가 지금까지 쌓아둔 것(스택 맨 위)보다
크면, 어차피 앞자리는 큰 숫자가 유리하니 작은 걸 지우고 큰 걸 앞에 두는 게 이득"이라는
그리디 판단을 스택으로 구현한다.
```python
number = "1924"
k = 2   # 지울 개수
stack = []
to_remove = k
for digit in number:
    while stack and to_remove > 0 and stack[-1] < digit:
        stack.pop()          # "1" 뒤에 "9"가 오면 "1"이 작으므로 지움
        to_remove -= 1
    stack.append(digit)
# stack이 다 채워진 뒤 to_remove가 남아있으면 뒤에서 마저 자름
result = ''.join(stack[:len(stack)-to_remove])  # "94"
```

### 상황 C: 구간을 최소 개수로 덮기 (단속카메라류)
차량 이동 구간이 `[[-5,-3],[-3,1],[1,3]]`처럼 여러 개 주어지고, 모든 구간을 최소
몇 대의 카메라로 다 지나가게 찍을 수 있는지 구한다고 하자("단속카메라"류). 구간을
**끝나는 지점 기준**으로 정렬하면, 가장 먼저 끝나는 구간의 끝점에 카메라 하나를
놓는 게 항상 손해가 아니다(그 카메라로 커버 못 하는 뒤쪽 구간은 어차피 따로 카메라가
필요했을 것이므로).
```python
intervals = [[-5,-3], [-3,1], [1,3]]
intervals.sort(key=lambda x: x[1])   # 끝나는 지점 기준 정렬
count, last = 0, float('-inf')
for start, end in intervals:
    if start > last:          # 지금 놓인 카메라 위치(last)로 이 구간을 못 덮으면
        count += 1
        last = end             # 새 카메라를 이 구간의 끝점에 놓음
# count == 2
```

## 3. 자주 하는 실수
- **그리디가 항상 최적이라는 증명 없이 "느낌"으로 접근** — 안 되면 DP나 완전탐색으로
  전환할 수 있어야 함 (막혔을 때 유형을 의심하는 것도 힌트 1단계의 역할)
- 정렬 기준을 잘못 잡음 (오름차순/내림차순, 시작점/끝점 기준을 헷갈림)
- 동점 처리 규칙을 안 정함

  두 노트를 먼저 다시 확인
