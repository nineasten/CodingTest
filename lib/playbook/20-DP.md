# DP (동적계획법)

## 1. 언제 이 기술인가 — 문제 속 신호
"최댓값/최솟값/경우의 수를 구하라"인데 완전탐색은 너무 크고(03번 표 초과), **같은 부분
문제가 여러 번 반복해서 등장**할 때. "N번째 값이 이전 값들로 정의된다"는 점화식이
보이면 DP. 시험에서는 Lv.3 초반까지만 대비한다 — 고급 DP는 4주 안엔 안 나온다.

## 2. 상황별 한국어 설명 + 예시 코드

### 상황 A: 1차원 DP — "이전 한두 개 상태로 지금을 정의"
피보나치 수 `n=5`를 구한다고 하자. `f(5)`를 구하려고 `f(4)+f(3)`을 재귀로 매번 처음부터
다시 계산하면 같은 값을 계속 다시 구하느라 지수적으로 느려진다("겹치는 부분 문제"가
DP의 핵심 신호). 대신 작은 것부터 배열에 순서대로 채워나가면 각 값을 딱 한 번씩만
계산한다.
```python
n = 5
dp = [0] * (n + 1)
dp[1] = 1
for i in range(2, n + 1):
    dp[i] = (dp[i-1] + dp[i-2]) % 1234567   # 나머지 연산 조건이 자주 붙는다
# dp = [0, 1, 1, 2, 3, 5] → dp[5] == 5
```

### 상황 B: 2차원 DP — "행/열 두 축의 상태를 함께 관리"
정수 삼각형 `[[7],[3,8],[8,1,0],[2,7,4,4]]`의 꼭대기에서 시작해 바로 아래-왼쪽 또는
아래-오른쪽으로만 내려가며 지날 수 있는 숫자의 합이 최대가 되는 경로를 찾는다고
하자("정수 삼각형"류). `dp[r][c]`를 "r행 c열까지 내려왔을 때 가능한 최댓값 합"으로
정의하면, 그 값은 바로 위 행의 두 후보(`dp[r-1][c-1]`, `dp[r-1][c]`) 중 큰 쪽에
현재 칸 값을 더한 것이다.
```python
triangle = [[7], [3,8], [8,1,0], [2,7,4,4]]
dp = [[0]*len(row) for row in triangle]
dp[0][0] = triangle[0][0]
for r in range(1, len(triangle)):
    for c in range(len(triangle[r])):
        candidates = []
        if c > 0: candidates.append(dp[r-1][c-1])          # 왼쪽 위에서 내려옴
        if c < len(triangle[r-1]): candidates.append(dp[r-1][c])  # 바로 위에서 내려옴
        dp[r][c] = max(candidates) + triangle[r][c]
answer = max(dp[-1])   # 마지막 행에서 가장 큰 값이 정답
```

### 상황 C: 조건이 붙은 DP ("같은 열을 연속으로 밟을 수 없다" 류)
땅 `[[1,2,3,5],[5,6,7,8],[4,3,2,1]]`을 한 행씩 내려가며 각 행에서 칸 하나씩 밟아
점수를 더하는데, **바로 전 행에서 밟았던 열은 이번 행에서 못 밟는다**는 제약이
있다("땅따먹기"류). 그래서 `dp[r][c]`는 "직전 행의 c를 제외한 나머지 열 중 최댓값"에
현재 칸 값을 더해야 한다 — 단순히 "이전 행 최댓값"만 보면 틀린다.
```python
land = [[1,2,3,5],[5,6,7,8],[4,3,2,1]]
dp = [row[:] for row in land]
for r in range(1, len(land)):
    for c in range(4):
        dp[r][c] = max(dp[r-1][k] for k in range(4) if k != c) + land[r][c]
answer = max(dp[-1])
```

### 상황 D: 재귀 + 메모이제이션 (탑다운)
점화식 자체는 "동전 여러 종류로 금액 K를 만드는 경우의 수"처럼 명확한데, 반복문으로
"어떤 순서로 채워야 할지"가 헷갈릴 때가 있다. 이럴 땐 점화식을 그대로 재귀 함수로
옮기고 `lru_cache`를 씌우면, "이미 계산한 (i, 남은금액) 조합은 다시 계산 안 하고
캐시에서 바로 꺼낸다"는 DP의 핵심 효과를 그대로 얻으면서 코드는 더 직관적이다.
```python
from functools import lru_cache

coins = (1, 5, 10)   # 리스트가 아니라 튜플이어야 캐시 키로 쓸 수 있음
@lru_cache(maxsize=None)
def solve(i, remain):
    if remain == 0:
        return 1
    if i == len(coins) or remain < 0:
        return 0
    return solve(i+1, remain) + solve(i, remain - coins[i])   # i번 동전을 안 쓴다 / 더 쓴다
```

## 3. 자주 하는 실수
- 점화식을 세우지 않고 바로 코드부터 침 — 반드시 `dp[i]가 무엇을 의미하는지`를 말로
  먼저 정의하고 시작 (힌트 3단계에서 이걸 요구하는 이유)
- 초기값(base case)을 빠뜨림 — `dp[0]`, `dp[1]` 등 경계 처리
- 2차원 DP에서 인덱스 범위를 벗어나는 접근 (상황 B의 `if c > 0` 같은 가드를 빼먹음)
- **DP인 줄 모르고 완전탐색으로 접근해 시간초과** — 03번 표에서 N이 크고, 하위 문제가
  겹친다는 느낌이 들면 DP를 의심할 것

## 4. Python 잡기술
- `functools.lru_cache` — 재귀 DP를 짧게 짤 때. 인자가 리스트면 캐시 안 되니 튜플로
- 공간을 줄이려면 `dp[i]`가 `dp[i-1]`만 참조하는 경우 배열 전체 대신 변수 두 개만 유지
  (롤링 배열) — 시간엔 영향 없지만 메모리 절약, 리뷰에서 언급할 만한 최적화
