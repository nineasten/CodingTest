# DP (동적계획법)

## 1. 언제 이 기술인가 — 문제 속 신호
"최댓값/최솟값/경우의 수를 구하라"인데 완전탐색은 너무 크고(03번 표 초과), **같은 부분
문제가 여러 번 반복해서 등장**할 때. "N번째 값이 이전 값들로 정의된다"는 점화식이
보이면 DP. 시험에서는 Lv.3 초반까지만 대비한다 — 고급 DP는 4주 안엔 안 나온다.

## 2. 상황별 한국어 설명 + 예시 코드

### 상황 A: 1차원 DP — "이전 한두 개 상태로 지금을 정의"
피보나치류. `dp[i]`가 `dp[i-1]`, `dp[i-2]`로 정의되는 가장 단순한 형태.
```python
dp = [0] * (n + 1)
dp[1] = 1
for i in range(2, n + 1):
    dp[i] = (dp[i-1] + dp[i-2]) % MOD    # 나머지 연산 조건이 자주 붙는다
```

### 상황 B: 2차원 DP — "행/열 두 축의 상태를 함께 관리"
정수 삼각형, 땅따먹기류. `dp[r][c]` = "r행 c열까지 왔을 때의 최적값". 이전 행의 값들로
현재 행을 채운다.
```python
dp = [[0]*len(row) for row in triangle]
dp[0][0] = triangle[0][0]
for r in range(1, len(triangle)):
    for c in range(len(triangle[r])):
        candidates = []
        if c > 0: candidates.append(dp[r-1][c-1])
        if c < len(triangle[r-1]): candidates.append(dp[r-1][c])
        dp[r][c] = max(candidates) + triangle[r][c]
answer = max(dp[-1])
```

### 상황 C: 조건이 붙은 DP ("같은 열을 연속으로 밟을 수 없다" 류)
"땅따먹기"류 — 단순 최댓값이 아니라 "직전에 뭘 골랐는지"까지 상태에 포함해야 할 때가
많다. 이번 행의 각 열에서 "직전 행의 같은 열만 빼고 최댓값"을 취한다.
```python
for r in range(1, n):
    for c in range(4):
        dp[r][c] = max(dp[r-1][k] for k in range(4) if k != c) + land[r][c]
answer = max(dp[-1])
```

### 상황 D: 재귀 + 메모이제이션 (탑다운)
점화식은 알겠는데 반복문으로 순서를 짜기 애매하면, 재귀에 캐시를 씌우는 게 더 직관적일
때가 있다.
```python
from functools import lru_cache

@lru_cache(maxsize=None)
def solve(i, state):
    if base_case(i, state):
        return base_value
    return combine(solve(i+1, next_state1), solve(i+1, next_state2))
```

## 3. 자주 하는 실수
- 점화식을 세우지 않고 바로 코드부터 침 — 반드시 `dp[i]가 무엇을 의미하는지`를 말로
  먼저 정의하고 시작 (힌트 3단계에서 이걸 요구하는 이유)
- 초기값(base case)을 빠뜨림 — `dp[0]`, `dp[1]` 등 경계 처리
- 2차원 DP에서 인덱스 범위를 벗어나는 접근 (상황 B의 `if c > 0` 같은 가드를 빼먹음)
- **DP인 줄 모르고 완전탐색으로 접근해 시간초과** — 03번 표에서 N이 크고, 하위 문제가
  겹친다는 느낌이 들면 DP를 의심할 것

## 4. Python 잡기술
- `functools.lru_cache` — 재귀 DP를 짧게 짤 때. 인자가 리스트면 캐시 안 되니 튜플로
- 공간을 줄이려면 `dp[i]`가 `dp[i-1]`만 참조하는 경우 배열 전체 대신 변수 두 개만 유지
  (롤링 배열) — 시간엔 영향 없지만 메모리 절약, 리뷰에서 언급할 만한 최적화
