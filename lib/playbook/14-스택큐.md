# 스택 · 큐

## 1. 언제 이 기술인가 — 문제 속 신호
"가장 최근에 넣은 것부터 처리"(스택), "먼저 들어온 것부터 처리"(큐), "괄호가 짝이 맞는지",
"순서대로 대기열을 처리", "현재 원소보다 뒤에 오는 더 큰/작은 값" 이 나오면 이것.

## 2. 상황별 한국어 설명 + 예시 코드

### 상황 A: 괄호/짝 맞추기 (스택의 전형)
여는 괄호는 넣고, 닫는 괄호가 오면 스택 맨 위와 짝이 맞는지 확인 후 뺀다.
```python
stack = []
for ch in s:
    if ch in '([{':
        stack.append(ch)
    else:
        if not stack or not matches(stack.pop(), ch):
            return False
return not stack   # 끝나고 남은 게 있으면 짝이 안 맞은 것
```

### 상황 B: 대기열 시뮬레이션 (큐)
프로세스/프린터 유형 — "우선순위가 더 높은 게 뒤에 있으면 기다린다". 큐에서 꺼낸 원소가
조건을 만족 못 하면 다시 맨 뒤로 보낸다.
```python
from collections import deque
q = deque(enumerate(priorities))   # (원래인덱스, 값)
order = []
while q:
    idx, val = q.popleft()
    if any(val < other for _, other in q):
        q.append((idx, val))       # 다시 맨 뒤로
    else:
        order.append(idx)
```

### 상황 C: "다음의 더 큰/작은 값"을 찾는 문제 (모노토닉 스택)
"주식가격", "다음 더 큰 원소" 류 — 스택에 인덱스를 쌓아두고, 현재 값이 스택 맨 위보다
크면 그 인덱스는 답이 확정되므로 pop하며 계산한다. 이중 for문(O(N²))을 O(N)으로 줄이는
대표 패턴.
```python
stack = []   # 인덱스 저장
answer = [0] * len(arr)
for i, val in enumerate(arr):
    while stack and arr[stack[-1]] < val:
        j = stack.pop()
        answer[j] = i - j   # 예: j번째가 몇 칸 뒤에서 더 큰 값을 만났는지
    stack.append(i)
```

## 3. 자주 하는 실수
- 큐를 `list`로 만들고 `pop(0)` 사용 — O(N)이라 시간초과. **deque 필수**
- 스택이 비었는지 확인 안 하고 `pop()` — IndexError. 항상 `if stack:` 먼저 체크
- 우선순위 큐가 필요한데 일반 큐/리스트로 매번 최댓값을 선형 탐색 — 힙(15번 노트)으로 바꿀 것

## 4. Python 잡기술
- `deque.rotate(n)` — 큐를 n칸 회전 (원형 큐 시뮬레이션에 유용)
- 인덱스와 값을 함께 넣기: `deque(enumerate(arr))` — 원래 순서를 잃지 않고 처리
