# 공통: 파이썬 자료형 선택

## 1. 언제 이 기술인가 — 문제 속 신호
모든 문제의 시작점. "존재하는지 빠르게 확인", "중복 제거", "순서를 유지해야", "앞/뒤에서
넣고 빼야" 같은 문구가 자료형 선택을 결정한다. 자료형을 잘못 고르면 로직은 맞아도
시간초과가 난다.

## 2. 상황별 한국어 설명 + 예시 코드

### 상황 A: "포함되어 있는지"를 반복해서 확인해야 할 때 → set
방문 기록 10만 개짜리 리스트 `visited_ids`가 있고, 새 사용자 10만 명이 들어올 때마다
"이미 방문한 적 있는 아이디인가?"를 매번 확인해야 한다고 하자. `visited_ids`가 리스트면
`id in visited_ids` 한 번이 최악의 경우 리스트 전체(10만)를 훑어야 해서, 10만 번
반복하면 전체가 100억 번 비교(O(N²))가 되어 시간초과가 난다. `set`으로만 바꾸면
같은 검사가 평균 O(1)이라 전체가 O(N)으로 끝난다.
```python
seen = set(arr)
if target in seen:   # list였다면 O(N), set이면 평균 O(1)
    ...
```

### 상황 B: 값과 값을 짝지어 빠르게 찾아야 할 때 → dict
투표 결과 `["A","B","A","C","A","B"]`에서 "각 후보가 몇 표를 받았는지"를 세야 한다고
하자. 직접 반복문으로 `if v not in cnt: cnt[v] = 0` 같은 방어 코드를 매번 짜는 대신,
`Counter`는 "개수 세기"에 특화된 dict라 한 줄로 끝난다.
```python
from collections import Counter
cnt = Counter(["A","B","A","C","A","B"])   # {'A': 3, 'B': 2, 'C': 1}
cnt.most_common(1)                          # [('A', 3)] — 가장 많이 나온 것부터
```

### 상황 C: 앞/뒤 양쪽에서 넣고 빼야 할 때 → deque
프린터 대기열처럼 "맨 앞 사람을 꺼내 처리하고, 조건이 안 맞으면 다시 맨 뒤로 보낸다"는
로직을 리스트로 짜면 `queue.pop(0)`(맨 앞 꺼내기)이 매번 O(N)이라 대기열이 길수록
느려진다. `deque`는 양쪽 끝 삽입/삭제가 전부 O(1)이라 큐 시뮬레이션엔 항상 이걸 쓴다.
```python
from collections import deque
q = deque([1, 2, 3])
q.popleft()      # 1을 꺼냄, O(1) — list.pop(0)은 O(N)이라 절대 쓰지 말 것
q.append(4)      # 맨 뒤에 4 추가 → deque([2, 3, 4])
q.appendleft(0)  # 맨 앞에 0 추가 → deque([0, 2, 3, 4])
```

### 상황 D: 순서 없이 중복만 없애면 될 때 → set, 순서를 지켜야 할 때 → dict.fromkeys
로그 `["b","a","b","c","a"]`에서 "등장한 이름 목록"만 필요하고 순서는 상관없다면
`set(arr)`이 가장 짧다. 반대로 "**처음 등장한 순서대로** 중복만 제거"해야 한다면
(예: `["b","a","c"]`가 나와야 하고 `{"a","b","c"}`처럼 순서가 뒤섞이면 안 될 때)
`set`은 순서를 보장하지 않으므로 못 쓴다. 이럴 땐 파이썬 3.7+에서 삽입 순서를 보존하는
`dict`의 키만 남기는 트릭을 쓴다.
```python
arr = ["b", "a", "b", "c", "a"]
unique_no_order = set(arr)                    # {'a', 'b', 'c'} — 순서 보장 안 됨
unique_keep_order = list(dict.fromkeys(arr))  # ['b', 'a', 'c'] — 처음 나온 순서 유지
```

### 상황 E: 짝을 지어 정렬·비교해야 할 때 → tuple
격자 위에서 BFS를 돌 때 "이 좌표를 이미 방문했는가"를 확인해야 한다. 좌표는 `(행, 열)`
두 값이 한 쌍이어야 의미가 있는데, 리스트 `[r, c]`는 값을 바꿀 수 있어(가변) set의
원소나 dict의 키로 쓸 수 없다(에러: `unhashable type: 'list'`). 튜플 `(r, c)`는
값을 못 바꾸는(불변) 대신 바로 set/dict에 넣을 수 있다.
```python
visited = set()
visited.add((2, 3))          # 2행 3열을 방문 처리
(2, 3) in visited             # True — 좌표 쌍을 그대로 키처럼 씀
```

## 3. 자주 하는 실수
- 큰 리스트에서 `x in list`를 반복 — O(N²)이 되어 시간초과. set/dict로 바꿀 것
- 큐를 `list`로 만들고 `pop(0)` — deque로 바꿀 것
- 딕셔너리 순회 중 딕셔너리를 수정 — `RuntimeError`. `list(d.items())`로 복사 후 순회

## 4. Python 잡기술
- `dict.get(key, default)` — 키가 없을 때 기본값. `if key in d` 검사를 줄여줌
- `collections.defaultdict(int)` — 없는 키 접근 시 자동으로 0 생성, 누적합에 유용
- 리스트 컴프리헨션이 for문보다 대체로 빠르다: `[x*2 for x in arr if x > 0]`
