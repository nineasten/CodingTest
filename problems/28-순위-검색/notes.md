# 순위 검색 (72412)

## 핵심 아이디어
**Preprocessing으로 계산을 다 때려버리기**: info의 각 지원자 점수를 4개 필드마다 "원래값/'-'" 
조합 16가지에 모두 저장. 그러면 나중에 와일드카드를 포함한 쿼리도 정확한 키 하나로 
O(1) 조회 가능 → O(logN) bisect만 하면 됨.

- 완전탐색 O(N×M): 쿼리마다 info 전체 순회
- 이 방식 O((N+M)logN): 계산 다 선행, 조회는 빠르게

## 주요 기술
- `defaultdict(list)` + `product` → 16개 조합 키 생성
- `bisect_left` + 반대 계산(`len - pos`) → "점수 이상인 개수"
- 튜플 키의 일관성 유지 (info 저장 시, 쿼리 조회 시 형식 맞추기)

## 복잡도
O((N+M)×16×logN), N=50k, M=100k → 여유 충분

## 깨달음
쿼리마다 16개 조합을 만들고 일일이 찾는 게 아니라, **info를 미리 16개로 폭발시켜두고**
쿼리는 그냥 있는 그대로 키로 만들기. 이게 핵심.
