# 풀이 기록

## 막힌 지점

`while queue[-1] == result[0]:` 에서 `IndexError` — 안쪽 while이 반복되는 동안
queue가 완전히 빌 수 있다는 걸 놓침. `if queue:`는 바깥에서 1번만 검사했는데
안쪽 while은 여러 번 도는 루프라 재검사가 필요했음. `queue and queue[-1] == ...`로 수정.

## 풀이 전략 (제출한 버전)

뒤에서부터 pop하며 `result`(deque) 앞에 넣고, `result[0]`과 큐의 마지막 원소가
같으면 계속 스킵.

## 핵심 인사이트

연속 원소 판정은 앞/뒤 어느 방향으로 훑든 "직전에 채택한 값과 비교"만 하면 된다.
더 간단한 표준형은 **앞에서부터 순회 + `result[-1]`과 비교**:
```python
result = []
for x in arr:
    if not result or result[-1] != x:
        result.append(x)
```

## 복잡도

- 시간: O(N), 공간: O(N)

## 결과

통과 (0/4 힌트 — 힌트 요청 없이 직접 디버깅으로 해결)

## 교훈

1. while 루프 안에서 반복적으로 pop하는 경우, "비었는지" 체크는 **매 반복마다** 필요.
   바깥에서 1번 검사한 것으로는 안쪽 반복 도중의 상태 변화를 못 잡음.
2. `queue = arr`처럼 원본 리스트를 그대로 대입하면 `pop()`이 호출자의 리스트를
   파괴함 — 함수 내부에서 변형할 거면 `arr[:]`로 복사.
