# 풀이 기록

## 결과
✅ 통과 (힌트 1단계 사용)

## 막힌 지점
1. **최초 구현**: 방향벡터 `dx=[-1,1,0,0], dy=[0,0,-1,1]` 4개를 두고 `for i in range(3)`으로
   순회 — 한 방향이 통째로 빠짐. 동시에 `neighbors`에 벽 체크(`maps[n_x][n_y]`)가
   조건에 아예 없었음. `/hint` 1단계(관찰 질문: "dx/dy 개수와 range 값이 같나요?
   이동을 막는 조건이 그것뿐인가요?")로 둘 다 스스로 발견하고 수정.
2. **리팩토링 중 재발**: `neighbors` 함수를 없애고 `zip(dx, dy)`로 BFS 루프 안에 합치는
   과정에서 새 버그 2개 도입:
   - `deque([0, 0, 1])`처럼 큐 초기값을 리스트로 한 번 더 안 감싸 정수 3개가 개별
     원소로 들어감 → `cur[0]`에서 `TypeError: 'int' object is not subscriptable`
   - `neighbor`를 `[x, y]`(list)로 만들면서 도착 판정은 `neighbor == (n-1, m-1)`
     (tuple)로 비교 — list와 tuple은 값이 같아도 `==`가 항상 False라 도착을 영영
     못 찾고 `-1` 반환. `visited`도 tuple로 넣게 통일해서 해결.

## 배운 것
- 이동 가능 조건은 "범위 + 벽 + visited" 세트로 항상 같이 챙길 것. 방향벡터
  개수(len(dx))와 순회 범위(range(n))가 일치하는지 짜자마자 눈으로 대조.
- 좌표 상태를 튜플/리스트 중 하나로 정하면 큐·visited·비교 전부 그 타입으로 통일.
  리팩토링(함수 합치기 등) 중에 이 통일성이 제일 쉽게 깨짐 — 리팩토링 직후엔
  자료형 일관성부터 재확인.
