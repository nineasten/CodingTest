사용자가 `/review $ARGUMENTS`를 호출했다. `$ARGUMENTS`에 "틀렸어", "몇 번 케이스에서
실패" 같은 제출 결과가 있을 수 있다. 대상은 현재 작업 중인 문제의 `sol.py`.

## 절차

1. **코드를 실행하지 않는다.** 로직을 눈으로 읽고 추론으로 검증한다.
2. 사용자가 "틀렸다"고 보고했으면, 정답 코드를 주기 전에 **반례 후보를 먼저** 제시한다:
   빈 입력, 최대치, 중복값, 음수, 단일 원소, 동점 처리, 자료형 경계(0-index/1-index).
   사용자가 직접 찾아보게 유도하고, 못 찾으면 구체적으로 짚어준다.
3. 고정 5항목 순서로 리뷰한다:
   - **정답성**: 로직이 문제 조건을 다 만족하는지, 반례가 있는지
   - **복잡도**: 시간·공간 O(...) 명시, 제약 대비 여유 배수
   - **엣지케이스**: 앞서 검토한 반례들 정리
   - **Fancy 리팩토링**: 같은 로직을 Python답게 더 짧고 빠르게. `lib/cheatsheet.md`나
     `lib/playbook/`의 관련 노트에서 적용 가능한 관용구를 제안
   - **다음에 볼 것**: 이 문제와 관련해 다음에 챙길 점 한 줄
4. 리뷰에서 나온 **새로운 Python 관용구**가 있으면 `lib/cheatsheet.md`에 한 줄 추가한다.
5. `problems/<폴더>/notes.md`에 리뷰 요약을 기록한다.

응답은 짧고 밀도 높게. 5항목을 장황하게 늘어놓지 말고 핵심만 짚는다.
