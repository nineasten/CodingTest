사용자가 `/next` (뒤에 유형이 붙을 수도 있음: `$ARGUMENTS`)를 호출했다. 다음 순서로
진행한다.

## 1. 선정

1. `PROGRESS.md`의 커버리지 보드를 읽는다. `$ARGUMENTS`에 유형이 지정됐으면 그 유형에서,
   아니면 **아직 안 채운 가장 낮은 층**을 찾고 그 층에서 비중 높은 유형 순으로 고른다
   (비중순: 구현·시뮬레이션 > 2D격자·문자열파싱·해시·정렬·스택큐 > BFS·DFS·완전탐색 >
   힙·그리디·이분탐색·DP).
2. `review/mistakes.md`를 읽어 3회 이상 쌓인 태그가 있으면 그 약점 유형을 우선한다.
3. 직전 문제 결과를 반영: 힌트 없이(0~1단계) 풀었으면 한 칸 위 난이도, 3단계 이상
   힌트를 썼으면 같은 칸에서 다른 문제로 재도전.
4. `PROGRESS.md` 상단의 목표일과 남은 빈 칸 수로 페이스를 계산한다. 뒤처져 있으면
   쉬운 칸(L1~L2하)을, 앞서 있으면 어려운 칸을 우선한다. 목표일이 임박(D-7 이내)하면
   모의고사·재풀이 비중을 높이라고 짧게 제안한다.
5. `curriculum/problem-bank.md`에서 위 조건에 맞고 아직 안 낸(`상태: 미출제`) 문제를
   고른다. **은행에 적합한 문제가 없으면, 새 문제를 WebFetch로 URL을 열어 제목이
   일치하는지 확인한 뒤에만 은행에 행을 추가하고 사용한다. 확인 없이 지어낸 URL을
   제시하지 않는다.**

## 2. 처음 만나는 유형이면 플레이북 요약

이 유형으로 `/next`를 낸 적이 없으면(=`PROGRESS.md` 로그에 해당 유형 기록이 없으면),
`lib/playbook/`의 해당 노트에서 **1번(신호)과 2번의 가장 기본적인 상황 1~2개**를
짧게 요약해 먼저 보여준다. 전체 노트를 다 읽어주지 않는다(그건 `/learn`의 역할).

## 3. 제시

아래 고정 포맷으로 제시한다:

```
─────────────────────────────────────────────
출처: 프로그래머스 · <카테고리>
문제: <제목>   (문제 ID <ID>)
링크: <전체 URL>
난이도: <Lv> | 보드 칸: <유형> <난이도칸>
─────────────────────────────────────────────
제약: <문제의 제약 조건 요약> → 목표 O(...)
고른 이유: <직전 결과나 페이스에 근거한 한 줄>
목표 시간: <분>
```

복잡도와 목표 시간은 문제 제약을 보고 Claude가 계산한다. 사용자에게 역산을 요구하지
않는다.

## 4. 폴더 생성

`problems/<두자리번호>-<문제명(한글, 공백은 -로)>/` 폴더를 만들고:

- `problem.md`: 출처·ID·URL·난이도·카테고리, 문제 요약, 제약, 입출력 예시, 목표 복잡도
- `sol.py`: 아래 헤더로 시작하는 빈 파일

```python
# ─────────────────────────────────────────────────────────
# 프로그래머스 · <카테고리>
# [<ID>] <제목>  (<Lv>)
# <전체 URL>
# 보드 칸: <유형> <난이도칸>   |   목표: <분>분 / O(...)
#
# 시작: <YYYY-MM-DD HH:MM>
# 힌트: ○○○○  (0/4)
# ─────────────────────────────────────────────────────────


def solution():
    pass
```

`notes.md`는 빈 파일로 만든다 (`/retro`가 채움).

번호는 이미 만들어진 `problems/` 폴더 수 + 1로 매긴다.

마지막에 `curriculum/problem-bank.md`에서 이 문제의 `상태`를 `사용중`으로 갱신한다.
