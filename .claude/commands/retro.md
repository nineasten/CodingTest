사용자가 방금 끝낸 문제에 대해 `/retro`를 호출했다. **사용자는 아무것도 적지 않는다
— 세션 기록을 근거로 Claude가 전부 작성한다.**

## 1. 원인 판단 (자동, 확정 전 확인)

해당 `sol.py` 헤더(힌트 게이지, 시각 기록)와 대화 맥락을 근거로:
- 몇 단계 힌트를 썼는지, 어디서 멈췄는지
- 제출이 몇 번 틀렸는지, 리뷰에서 뭘 지적했는지
를 보고 원인 태그를 하나 이상 고른다. 태그 예시:
`#유형인식실패` `#복잡도역산누락` `#인덱스오프바이원` `#자료구조선택`
`#엣지케이스누락` `#구현속도` `#동점처리누락` `#범위체크누락`

**확정 전 한 줄로 확인받는다**: "원인을 `#자료구조선택`으로 기록할게요 — 맞나요?"
사용자가 정정하면 그걸로 기록한다.

## 2. 파일 갱신

- **`problems/<폴더>/notes.md`**: 막힌 지점, 제출 결과, 배운 것, 원인 태그
- **`review/mistakes.md`**: 해당 태그 횟수 +1, 관련 문제 추가. **같은 태그가 3회
  이상이면** 응답에서 "이 약점만 모아서 `/drill` 하는 걸 제안합니다"라고 먼저 말한다
- **`review/queue.md`**: 오늘 날짜 기준 D+1/D+3/D+7/D+21 재풀이 일정 행 추가
- **`INSIGHTS.md`**: 해당 유형 섹션을 갱신. 새 신호/함정/틀린 이력이면 추가, 이미
  있으면 더 정확하게 다듬는다. "내가 틀린 이력"에 이번 문제 추가
- **`PROGRESS.md`**:
  - 커버리지 보드에서 해당 칸을 판정 — 힌트 2단계 이내로 풀었으면 `✅`, 3단계
    이상이거나 오래 걸렸으면 `⚠`
  - 문제 로그 표에 한 행 추가 (날짜·유형·난이도·소요시간·힌트단계·결과·한 줄 교훈)
- **`curriculum/problem-bank.md`**: 이 문제의 `상태`를 `완료`로 변경

## 3. 커밋 & 푸시

위 파일들을 stage하고 커밋한다. 커밋 메시지 형식:
```
[<보드칸>] <문제명> — <결과 태그 나열>
```
예: `[스택큐 L2-하] 프로세스 — #자료구조선택`

커밋 후 원격으로 푸시한다 (`git push`). 실패하면(원격 미설정 등) 사용자에게 알린다 —
21시 알림 파이프라인이 이 푸시에 의존한다.

## 4. 마무리

무엇을 기록했는지 3~4줄로 요약하고, 다음 행동(`/next` 등)을 제안한다.
